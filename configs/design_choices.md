# Per-stage design choices (A2 deliverable)

Corpus: *Twenty-second Annual Report of the Sanitary Commissioner for Bengal (1889)* — 836 scanned pages, 1890 letterpress, Internet Archive item `in.ernet.dli.2015.95111` (public domain).
Domain: public-health history · Data speciality: **unruled-tables+degraded-scans** · Primary NFR: **auditable (95% replayable audit trail)**.

**Implementation-grounded note:** this document describes the current `main` branch implementation/configuration. In particular, `configs/config.yaml` currently selects `device: cuda`; OCR, enhancement, and the notebook are written to fall back to CPU when CUDA is unavailable. The Stage 4 index is FAISS HNSW, not the older NumPy exact-index configuration mentioned in an earlier A2 form snapshot.

| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| 0 Frame | Turn the scanned corpus into a queryable KB; A2 builds the knowledge-base front half, with final answer quality judged in A3 by the A1 groundedness target (>=0.90). | 836 page images, no native text layer; held-out labelled pages live in `grading_kit/heldout_pages/`; corpus downloaded by `scripts/get_data.sh`. | — | A2 evidence: OCR quality and a working chunk/embed/store build. Final A3 metric: groundedness >=0.90 plus citation/evidence checks. | `task.yaml`, `manifest.yaml`, and `config.yaml` define corpus, entry points, and parameters. | Unit tests plus `notebooks/kb_demo.ipynb`; full build via `make ingest index` / `scripts/build_index.sh`. | Batch pipeline over the corpus; device is selected in `config.yaml` and stages auto-fall back to CPU where CUDA is unavailable. | Corpus/provenance artifacts are carried in `data/`; generated intermediate/index artifacts are rebuilt from the corpus rather than treated as source data. |
| 1 Ingest + Enhance | Convert scanned pages into OCR/layout-ready grayscale images and improve contrast/stroke quality before recognition. | PDF rendered at 200 DPI; preprocessing writes to `data/interim/processed`; enhancement writes to `data/interim/enhanced`. | Default **classical** enhancer `clahe_denoise`; optional from-scratch `unet_small`. | Preprocess: Gaussian blur `(3,3), sigma=0.8` -> Otsu threshold -> deskew when `|angle| > 0.5°`. Enhance: CLAHE `clipLimit=2.5`, tile `(8,8)` -> Gaussian blur sigma 1.0 -> unsharp via `addWeighted(1.5,-0.5)`. Optional UNet: 1->16->32->64 channels, self-supervised noisy->clean training. | `Page(id, image_path, doc_id)` is preserved; stages are cached on disk so reruns can reuse processed/enhanced images. Default config is classical enhancement with augmentation disabled; augmentation is used by the optional UNet training path. | Preprocess and enhancer are directly runnable; current `kb_demo.ipynb` demonstrates the one-page path and records CPU fallback when CUDA is unavailable. | Batch processing; `config.yaml` requests CUDA but enhancement resolves to CPU if PyTorch has no usable CUDA device. | Intermediate outputs are cached under `data/interim`; optional UNet checkpoint is stored under `data/interim/enhance/unet_small.pt`. |
| 2 Layout | Identify text/table/figure/heading regions and establish a stable reading order so OCR output can be mapped back to page regions. | Preprocessed/enhanced page images; no learned layout labels. | **Heuristic projection/contour**; no pretrained detector. | Otsu inverse threshold -> morphology close using size-derived kernels (`w/60`, `h/90` with minimums) -> connected components -> overlap/nearby-box merge. Classification uses ruling-line detection or whitespace-separated columns for tables, ink density for figures, and edge-position/height heuristics for headings. Reading order uses banded sorting by vertical position, then left-to-right within bands. | `Region(page_id, bbox, kind)` feeds Stage 3; region boundaries are retained for later chunking and source mapping. | Current notebook demonstrates layout on held-out page `bengal1889_p0018` and reports 3 detected regions. | CPU-friendly deterministic heuristic; no model training or detector serving. | Region counts/statistics can be logged during each build; a detector model remains an upgrade path if corpus complexity increases. |
| 3 OCR | Transcribe each page once and map detected OCR lines back into layout regions; preserve enough structure for degraded text and tables. | Enhanced page images; held-out `labels.jsonl` is an evaluation oracle where available. | **RapidOCR PP-OCRv4 ONNX**, pretrained detection + recognition, served by `rapidocr_onnxruntime`. | Page-level OCR is cached under `data/interim/ocr_cache/`; detected text boxes are assigned to regions by box-center containment. For `table` regions, optional table-cell recovery reconstructs row/column text with `" | "` separators without re-running recognition. `ocr.workers=2` enables a process pool; each worker owns its OCR engine. | Region input -> `Chunk(id, doc_id, text, page_ids)` output, with one initial chunk per region. Page-level recognition avoids repeating the recognizer for every region. | Current notebook runs RapidOCR on one held-out page and reports 3 OCR chunks. The implementation also supports backend comparison documented in the code: PaddleOCR PP-OCRv5 was tried but the installed CPU build crashed; EasyOCR worked but was slower/less accurate on this corpus. | Device comes from `config.yaml`; RapidOCR uses CUDA when a CUDA Execution Provider is available, otherwise CPU. The parent process keeps OCR on CPU while worker processes can use GPU to avoid the ORT/PyTorch CUDA-library conflict. | Per-page OCR JSON cache makes repeated index builds avoid re-running OCR; cache is under `data/interim/ocr_cache`. |
| 4 Index | Convert region-level OCR chunks into retrieval-sized windows, embed them, and persist a searchable vector index plus aligned metadata. | Input: `list[Chunk]` from OCR, one per layout region. No training labels are used for chunking/embedding/index construction. | Chunking: no trained model; `AutoTokenizer` loaded from `cfg['embed']['model']` is used as the token-counting ruler. Embedding: `sentence-transformers/all-MiniLM-L6-v2`, 384-d, pretrained and unmodified. Index: FAISS `IndexHNSWFlat`. | Fixed-size sliding windows with `chunk_tokens=256`, `overlap=32`, independently per OCR region; region boundaries are never crossed. Embedding uses `normalize_embeddings=True`, making inner product equivalent to cosine similarity. HNSW uses `METRIC_INNER_PRODUCT` and `M=32`. | `chunk.split()` creates ids `<region_id>-<window_idx>` -> `embed.encode()` returns one normalized vector per chunk in the same order -> `store.build()` writes `vectors.faiss` and row-aligned `chunks.jsonl` -> `store.load()` restores both. | `kb_demo.ipynb` currently demonstrates 3 OCR region-chunks -> 8 token windows -> 384-d embeddings -> store build/load round-trip with 8 vectors. The repo also contains small module-level sanity checks. There is no separate formal Stage 4 test suite in the current tree, so test coverage should be strengthened before final submission. | Config currently requests `device: cuda`; `SentenceTransformer` follows that runtime environment, while the current `embed.py` itself does not pass an explicit `device=` argument. Index construction is batch-style over the provided chunk list; FAISS data are materialized in memory before writing. | `data/index/` contains generated `vectors.faiss` and `chunks.jsonl`; these are derived artifacts and can be rebuilt with `scripts/build_index.sh`. `HNSW M=32` is currently hard-coded in `store.py`, so it is not fully parameterized by `config.yaml`. |
