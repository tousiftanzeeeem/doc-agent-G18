| 4 Index | Turn OCR'd region-chunks into a searchable vector index: re-chunk to retrieval-sized windows, embed each chunk, persist chunks+vectors so a query can find the top-k most relevant chunks. Success = every chunk is retrievable and ranked by true semantic similarity, not by chunk length or index artifacts. | Input: `list[Chunk]` from `vision/ocr.py` (one per detected layout region: id, doc_id, text, page_ids). Output: same `Chunk` type, re-windowed, plus a parallel `list[vector]`. No labels used — chunking/embedding/indexing are unsupervised/deterministic, not trained on this corpus. | Chunking: no model, just `AutoTokenizer` from `sentence-transformers/all-MiniLM-L6-v2` used as a token-counting ruler. Embedding: `sentence-transformers/all-MiniLM-L6-v2` (384-dim), pretrained, off-the-shelf, unmodified. Index: FAISS `IndexHNSWFlat`, not a trained model — a search data structure. | Chunking: fixed-size sliding window, `chunk_tokens=256`, `overlap=32` (from `configs/config.yaml`), applied independently per OCR region (region boundaries never crossed) — chosen over semantic/paragraph chunking for determinism and simplicity for a first pass. Embedding: `model.encode(..., normalize_embeddings=True)` — L2-normalize every vector so cosine similarity reduces to a plain dot product downstream. Index: HNSW built with `METRIC_INNER_PRODUCT` (not FAISS's default L2), `M=32` graph connectivity, so retrieval scores are cosine similarities (higher = better), consistent with the normalized embeddings and with `retrieve.weak_threshold` in Stage 5. | `chunk.split(chunks, cfg) -> list[Chunk]` (ids `<region_id>-<window_idx>`) → `embed.encode(chunks, cfg) -> list[vector]` (parallel, same order/length as chunks) → `store.build(chunks, vectors, cfg)` writes two things kept in sync by row position: `vectors.faiss` (the FAISS index — numbers only) and `chunks.jsonl` (id/doc_id/text/page_ids sidecar, since FAISS itself stores no metadata) → `store.load(cfg)` reloads both for querying. | Manually verified end-to-end with synthetic `Chunk`s (`scripts/dev_test_stage4.py`, dev-only, not a graded script): confirmed window count/overlap/ids for a >256-token region and a pass-through for a short region; confirmed `len(vectors) == len(chunks)` and each vector has `dim=384`; confirmed FAISS build→load→search round-trip returns the correct chunk with a ~1.0 self-similarity score. All model/index parameters live in `configs/config.yaml`, not hardcoded. No formal `tests/` unit test yet — TODO before final submission. | Runs on CPU (`device: cpu` in config; batch, not streaming). `embed.encode()` and `store.build()` are stateless functions called once per full corpus build via the pipeline; `SentenceTransformer`/tokenizer are cached per-process (loaded once, reused across calls) to avoid reloading on every chunk batch. Memory scales with corpus size — fine at class-project scale, would need batching/streaming for a much larger corpus. | `data/index/` (the built FAISS index + JSONL metadata) is a generated artifact — should be `.gitignore`d and rebuilt from `data/raw/` via `scripts/build_index.sh`, not committed. Nothing to monitor yet at this stage (no drift/retraining concern since chunking/embedding are deterministic/frozen-pretrained); would become relevant if the corpus grows incrementally and the index needs periodic rebuilding. |
