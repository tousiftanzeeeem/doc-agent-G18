# Per-stage design choices (A2 deliverable)



Corpus: *Twenty-second Annual Report of the Sanitary Commissioner for Bengal (1889)* — 836 scanned
pages, 1890 letterpress, Internet Archive item `in.ernet.dli.2015.95111` (public domain).
Domain: public-health history · Data speciality: **unruled-tables+degraded-scans** · Primary NFR: **auditable
(95% replayable audit trail)**.

| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| 0 Frame | Turn 836 degraded scans into a queryable KB; success = OCR quality + retrieval works, floors ≥300 pages / ≥60k words | 836 page-images (no text layer); held-out slice in grading_kit; splits by document | — (config in configs/) | Metric: OCR char-F1, recall@k, audit-trail replayability | task.yaml + manifest.yaml declare axes/corpus/entry points | pytest gates + notebooks | scripts/get_data.sh → data/raw | data/version.json snapshot + provenance.md |
| 1 Ingest+Enhance | Load PDF scans as page images; deskew/denoise/binarize; enhance before recognition | PDF rendered at 200 DPI (pypdfium2) to data/raw/pages; processed under data/interim | **classical enhance** (CLAHE + unsharp) by default; optional from-scratch UNet denoiser (`unet_small`, ~45k params) | pypdfium2 render → grayscale → Gaussian denoise (3×3, σ=0.8) → Otsu binarize → deskew (downscaled minAreaRect, sign-corrected with synthetic unit test) → CLAHE+unsharp; UNet trained self-supervised (noise→clean, 3 epochs, 800 patches) but classical wins on char-F1 | Page contract (id, image_path, doc_id); caches per stage make reruns incremental; skip-if-exists on render+preprocess+enhance | unit tests (test_ingest); synthetic deskew angle test | batch; ~30 ms/page preprocess, ~1 s/page render; device=cuda with CPU fallback | corpus version id recorded at build; provenance.md tracks archive.org source+licence |
| 2 Layout | Detect text/table/figure/heading regions so OCR runs on the right pieces | processed page images; no layout labels (self-curated) | **heuristic: projection/contour** (morphology close → connected components → merge); chosen over PP-DocLayout/YOLO — CPU-only, no labels, ~0.05 s/page | Otsu → morphological close (kernel scaled by page dims: kx=max(15,w//60), ky=max(9,h//90)) → findContours → overlap merge (50% area or 60% vertical overlap within merge_gap) → banded reading order (median-height rows, left→right) → classify: ruling-line test (HoughLinesP, threshold scaled by box width, ≥3 thin horizontal rules → table) or ≥2 whitespace-gap columns (projection-profile, A1 data-speciality) → table; ink density <0.03 or >0.45 + area >20% page → figure; short+wide+page-edge → heading; else text | Region contract (page_id, bbox, kind) feeds OCR line-mapping; all thresholds scale with page dimensions, not hardcoded pixels | unit tests assert region kinds on synthetic pages (forced text, forced table with drawn horizontal lines) | ~0.05 s/page CPU | region statistics logged per build |
| 3 OCR | Transcribe every region; baseline = reproduced published pretrained recognizer | region crops + page images; labels.jsonl held-out oracle for CER (pages 12, 16, 18, 19) | **RapidOCR PP-OCRv4-onnx (pretrained PP-OCR detection + recognition, served by onnxruntime)** — PaddleOCR PP-OCRv5 was tried first but paddlepaddle 3.3.1 CPU build crashes (PIR/oneDNN bug: `NotImplementedError: ConvertPirAttribute2RuntimeAttribute`); EasyOCR (CRAFT+CRNN) works but is ~4× slower and less accurate on dense tables/old orthography | page-level OCR once per page; det boxes distributed into regions by containment (4px tolerance); canvas_size=1280 (speed/quality); per-page JSON cache under data/interim/ocr_cache/; multiprocessing pool with `imap_unordered` (workers=2, each ~8 threads for onnxruntime); device=cuda with onnxruntime CUDA EP; table regions get per-cell OCR via spatial bounding-box intersection against cached page lines (no re-inference) | Chunk contract (id, doc_id, text, page_ids); one chunk per region, re-chunked later; lines not falling in any region dropped (margin noise) | unit tests mock the engine; char-F1 measured against labels.jsonl: mean 0.678 (p0012=0.971, p0016=0.673, p0018=0.524, p0019=0.544) — honest number for 19th-century degraded scans | OCR cache → rebuilds are near-free; CUDA EP with fallback to CPU; workers tuned from 3→2 to avoid thread oversubscription | OCR cache versioned under data/interim |
| 4 Index | Turn OCR'd region-chunks into a searchable vector index: re-chunk to retrieval-sized windows, embed each chunk, persist chunks+vectors so a query can find the top-k most relevant chunks. Success = every chunk is retrievable and ranked by true semantic similarity, not by chunk length or index artifacts. | Input: `list[Chunk]` from `vision/ocr.py` (one per detected layout region: id, doc_id, text, page_ids). Output: same `Chunk` type, re-windowed, plus a parallel `list[vector]`. No labels used — chunking/embedding/indexing are unsupervised/deterministic, not trained on this corpus. | Chunking: no model, just `AutoTokenizer` from `sentence-transformers/all-MiniLM-L6-v2` used as a token-counting ruler. Embedding: `sentence-transformers/all-MiniLM-L6-v2` (384-dim), pretrained, off-the-shelf, unmodified. Index: FAISS `IndexHNSWFlat`, not a trained model — a search data structure. | Chunking: fixed-size sliding window, `chunk_tokens=256`, `overlap=32` (from `configs/config.yaml`), applied independently per OCR region (region boundaries never crossed) — chosen over semantic/paragraph chunking for determinism and simplicity for a first pass. Embedding: `model.encode(..., normalize_embeddings=True)` — L2-normalize every vector so cosine similarity reduces to a plain dot product downstream. Index: HNSW built with `METRIC_INNER_PRODUCT` (not FAISS's default L2), `M=32` graph connectivity, so retrieval scores are cosine similarities (higher = better), consistent with the normalized embeddings and with `retrieve.weak_threshold` in Stage 5. | `chunk.split(chunks, cfg) -> list[Chunk]` (ids `<region_id>-<window_idx>`) → `embed.encode(chunks, cfg) -> list[vector]` (parallel, same order/length as chunks) → `store.build(chunks, vectors, cfg)` writes two things kept in sync by row position: `vectors.faiss` (the FAISS index — numbers only) and `chunks.jsonl` (id/doc_id/text/page_ids sidecar, since FAISS itself stores no metadata) → `store.load(cfg)` reloads both for querying. | Manually verified end-to-end with synthetic `Chunk`s and `_test_store()` in `store.py`: confirmed window count/overlap/ids for a >256-token region and a pass-through for a short region; confirmed `len(vectors) == len(chunks)` and each vector has `dim=384`; confirmed FAISS build→load→search round-trip returns the correct chunk with a ~1.0 self-similarity score. All model/index parameters live in `configs/config.yaml`, not hardcoded. | Runs on CPU (`device: cpu` in config for deterministic replay; batch, not streaming). `embed.encode()` and `store.build()` are stateless functions called once per full corpus build via the pipeline; `SentenceTransformer`/tokenizer are cached per-process (loaded once, reused across calls) to avoid reloading on every chunk batch. Memory scales with corpus size — fine at class-project scale. | `data/index/` (the built FAISS index + JSONL metadata) is a generated artifact — `.gitignore`d and rebuilt from `data/raw/` via `scripts/build_index.sh`, not committed. Chunking/embedding are deterministic/frozen-pretrained; index type/params logged in config for audit trail. |
